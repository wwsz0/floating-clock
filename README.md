# 悬浮时钟 · Floating Clock

使用 Swift / AppKit 编写的 macOS 原生悬浮时钟：可拖动、置顶、调整透明度，并通过可选的额度后端展示账号额度和常驻提醒气泡。无需第三方依赖。

> 时钟固定显示 **系统本地时间 + 16 小时**，不是普通的系统时间镜像。额度重置时间、成功更新时间使用相同的显示规则。

## 功能

### 时钟与外观

- 悬浮置顶，支持多个桌面，拖动后自动记住位置。
- 24 小时制，可显示或隐藏秒、日期；支持小、中、大三种字号。
- 支持锁定位置和鼠标穿透，可通过菜单栏时钟图标解锁。
- 底部齿轮可调整背景颜色与 0%–100% 透明度，默认透明度 85%，修改后立即生效并保存。

### 额度与提醒

- 本机与远端账号分块展示，包含剩余比例、进度条及重置时间，支持整体展开、收起和手动查询。
- 客户端每 **2 分钟**查询一次；网络失败时保留上次数据并标记连接失败。
- 仅在额度面板收起时冒泡。气泡可常驻、多条并存、逐条关闭，并跟随时钟移动。
- 气泡背景颜色、透明度随时钟变化；短弧线尾巴根据可用屏幕空间自动调整方向。
- 气泡内显示账户、累计下降、当前剩余及 **重置日期和时间**；无有效时间时显示“重置时间未知”。

## 编译与运行

需要 macOS 和 Apple Command Line Tools 提供的 `swiftc`。如果尚未安装 Command Line Tools，先运行：

```sh
xcode-select --install
```

获取源码并编译：

```sh
git clone https://github.com/wwsz0/floating-clock.git
cd floating-clock
./build.command
open '悬浮时钟.app'
```

编译脚本会生成并在本机签名 `悬浮时钟.app`。仓库不包含编译产物；脚本中的 SwiftBridging 兼容处理用于部分 Command Line Tools 环境。

## 常用操作

| 操作 | 入口 |
| --- | --- |
| 移动时钟 | 拖动窗口 |
| 展开或收起额度 | 时钟下方的展开／收起按钮 |
| 手动查询额度 | 底部“查询额度”按钮，或菜单栏 → 立即刷新额度 |
| 修改颜色、透明度 | 底部齿轮，或菜单栏 → 外观设置 |
| 设置鼠标穿透 | 菜单栏或右键菜单 → 锁定位置（鼠标穿透） |
| 恢复鼠标操作 | **菜单栏时钟图标 → 取消锁定位置（鼠标穿透）** |
| 设置提醒方向、开关或清除提醒 | 菜单栏 → 额度冒泡设置 |
| 预览气泡 | 先收起额度，再选择额度冒泡设置 → 测试提醒 |
| 找回移出屏幕的窗口 | 菜单栏 → 移回主屏幕右上角 |

更多说明见 [使用说明](使用说明.txt)。锁定后窗口按钮不会响应点击，但菜单栏仍可操作。

## 气泡提醒规则

首次提醒按以下规则触发：

| 额度类型 | 首次气泡门槛 |
| --- | --- |
| 组名为 `Claude and GPT models` 或 `Gemini 4 Argon` 的周额度 | 每跨 20 个百分点档位 |
| 其他周额度、Decodo 流量额度 | 每跨 4 个百分点档位 |
| 5 小时额度 | 降至 0% 提醒一次，从 0% 恢复为可用时再提醒一次 |

气泡出现后，**每比气泡上次显示的值再降低 1 个百分点，就原位更新同一气泡**；跳降多个百分点时也只更新一次，不新增重复气泡。5 小时恢复气泡更新时保留恢复样式。

- 每次收起面板时记录比较基准，气泡中的下降量始终相对此基准累计计算。替换气泡不会重置基准。
- 例如收起时剩余 80%，随后气泡在 76% 时显示下降 4 个百分点，更新到 75% 时显示下降 5 个百分点。
- 重置时间以小字显示为 `重置 M/D HH:mm`。查询发现时间变化时，会更新已有气泡，但不改变逐百分点更新的比较值。
- 手动关闭气泡后停止逐百分点追更，后续新气泡仍按首次门槛触发。
- 展开额度会立即清除气泡，展开期间不冒泡，也不积攒补弹；再次收起时记录新的比较基准。
- 不同额度的气泡可并存，溢出时可滚动查看；退出应用后不恢复旧气泡，已提醒状态和比较基准保存在本机。

## 额度服务（可选）

**此仓库仅提供 macOS 客户端，不包含额度后端、网络转发、Decodo 抓取脚本或浏览器登录配置。** 没有兼容后端时，额度区域会显示不可用，但时钟本身仍可使用。

服务地址在 `Quota.swift` 的 `QuotaLoader.baseURL` 中设置，默认仅访问本机回环地址 `http://127.0.0.1:8318`。修改地址后需重新编译。

| 查询 | 用途 |
| --- | --- |
| `GET /local/quota.json` | 本机额度 |
| `GET /remote/quota.json` | 远端额度 |
| `GET /local/quota.json?refresh_decodo=1` | 手动查询时请求后端刷新 Decodo，需后端支持 |

以下为最小响应示例，**账户和数值均为虚构数据**：

```json
{
  "updated_at": "2030-01-01T00:00:00Z",
  "accounts": [
    {
      "label": "示例账户",
      "provider": "example",
      "status": "ok",
      "windows": [
        {
          "label": "周额度",
          "remaining_percent": 80,
          "window_seconds": 604800,
          "reset_at": "2030-01-08T00:00:00Z"
        }
      ]
    }
  ]
}
```

### Decodo 新鲜度提示

配套后端当前采用 **每 15 分钟后台抓取**，手动查询可额外触发抓取。后台定时与去重必须由后端实现；单独编译或运行本客户端不会启动抓取任务。

Decodo 账户使用 `provider: "decodo"`，并可返回以下字段：

| 字段 | 含义 |
| --- | --- |
| `last_success_at` | 最近一次真正成功获取数据的 ISO 8601 时间，不是接口响应时间 |
| `refresh_interval_seconds` | 抓取及过期判断周期，当前为 `900` 秒 |
| `stale` | 数据是否已过期，或最近抓取是否失败 |
| `refreshing` | 是否正在抓取 |
| `status` | 新鲜数据为 `ok`；可参考的过期数据为 `stale`，保留其 `windows` |

卡片显示“上次成功”时间。达到过期周期或后端标记失败时，保留旧值并以橙色显示“数据已过期”，不对过期数据冒泡。客户端也会根据真实成功时间判断过期，避免把一次成功的接口响应误当成额度已刷新。

## 自检

编译后运行逻辑自检，不打开窗口、不查询真实额度：

```sh
'悬浮时钟.app/Contents/MacOS/FloatingClock' --self-test
```

界面自检使用隔离的测试偏好和虚构数据，会短暂显示测试窗口后退出：

```sh
'悬浮时钟.app/Contents/MacOS/FloatingClock' --alert-ui-self-test
```

启动时直接打开外观设置：

```sh
open '悬浮时钟.app' --args --show-settings
```

## 项目结构

| 文件 | 内容 |
| --- | --- |
| `main.swift` | 时钟、悬浮窗口、菜单和应用入口 |
| `Quota.swift` | 额度接口、账号卡片、进度条及新鲜度显示 |
| `Appearance.swift` | 颜色、透明度与偏好保存 |
| `QuotaAlerts.swift` | 提醒门槛、累计基准、同额度替换及气泡管理 |
| `QuotaSpeechBubble.swift` | 紧凑气泡、重置时间、尾巴与屏幕布局 |
| `QuotaAlertTests.swift` | 逻辑与界面自检 |
| `Info.plist` | 应用元数据 |
| `build.command`、`empty.modulemap` | 本地构建与工具链兼容处理 |

## 隐私与发布范围

- 公开内容仅含客户端源码、文档和虚构测试数据，不包含真实账户、API 密钥、个人目录、内网地址、后端配置、浏览器配置或登录凭据。
- 客户端只查询自行配置的额度服务，不读取密钥文件、不操作 VPN，也不需要辅助功能或屏幕录制权限。
- 位置、外观、提醒状态和累计比较基准保存在本机 UserDefaults，不随仓库发布。
- `.app`、构建缓存、生成的路径配置、日志、环境变量文件和密钥文件不纳入版本管理；请勿提交真实额度响应。
- 运行时会展示后端返回的账号标签和额度。公开分享自己的截图或日志前，请另外遮挡其中的真实账户信息。
